# 群晖部署规则

## 硬件约束

- Synology DS920+
- Intel J4125 四核四线程
- 20GB 内存
- 无独立 GPU
- 系统长期运行不依赖台式机

## 运行原则

- 不在群晖运行本地大模型（无 GPU，CPU 推理不满足要求）。
- AI 推理统一通过云端 DeepSeek API 完成。
- 群晖承担：采集、预筛、MongoDB、队列、API 调度、Web 管理和推送。

## 并发限制

| 组件 | 并发上限 |
|------|----------|
| 普通爬虫 | 2 |
| Playwright | 1 |
| PDF Worker | 1 |
| AI Worker | 1 |

## 内存与资源规划

- MongoDB WiredTiger 缓存目标：0.5GB。
- 需根据 J4125 和 20GB 内存合理限制各服务内存占用。
- 不启动本地嵌入模型（BGE-M3）和 VectorDB 服务（第一阶段关闭）。

## 磁盘规划

- 最低预留磁盘：100GB。
- 建议预留磁盘：200GB。
- 磁盘告警与降级策略：

| 使用率 | 动作 |
|--------|------|
| 70% | 告警，通知运维检查清理 |
| 85% | 严重告警，停止低优先级任务（如推送） |
| 95% | 紧急降级，停止采集与队列消费，仅保留核心查询与告警 |

- 日志必须轮转，避免无限增长耗尽磁盘。

## 部署结构（M7）

- 生产部署最终采用四容器结构：
  - china-watch-mongo；
  - china-watch-hub；
  - china-watch-crawler；
  - china-watch-notifier。
- Docker 化位于 M7，不得提前到 M0 或 M1。
- MongoDB 容器不得公开映射端口到公网。
- 管理界面不得直接公开公网，须通过内网访问或反代保护。
- 容器必须使用非 root 用户运行。
