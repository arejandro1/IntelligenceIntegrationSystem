# 测试规则

## 总原则

- 业务代码必须有测试。
- 普通测试不得调用真实 API。
- 不得删除失败测试以取得通过结果。
- 不得声称运行未运行的测试。

## 时间测试

- 时间相关测试必须使用 FakeClock（可注入的时钟），不得依赖系统真实时间。
- 峰谷时段、Guard 窗口、重试退避等时间策略测试必须使用 FakeClock 验证边界值。

## API 调用约束

- 普通测试不得调用真实 DeepSeek API 或任何真实付费 API。
- DRY_RUN 模式下真实调用次数必须为 0。
- 高峰时段的真实调用次数必须为 0（含 Flash、Pro、API 重试和付费健康检查）。
- 所有 API 调用必须通过可替换的客户端接口（依赖注入或 Mock），便于测试。

## 队列与并发测试

- 必须测试重启恢复：未完成队列项在重启后重新入队或标记待重试。
- 必须测试幂等：同一数据重复入队不得产生重复 AI 调用。
- 必须测试租约机制：处理中项超时自动释放。
- 必须测试并发认领：同一项不得被两个 worker 同时认领。
- 必须测试新旧 AI 消费者互斥：两者同时为 true 时启动失败。

## 测试覆盖要求

- 每个里程碑的测试用例必须覆盖该里程碑的验收标准。
- 边界值、错误路径和异常路径必须有测试。
- 配置缺失、配置非法时的行为必须有测试（fail-closed 验证）。

## 测试报告要求

- 测试结果必须如实报告通过、失败、跳过。
- 失败的测试不得声称完成。
- 未运行的测试不得声称已运行。
