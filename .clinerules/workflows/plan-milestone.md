# 里程碑规划流程

当前只能使用 Plan 模式，只读调查，不得修改文件。

请完成：

1. 只读调查：阅读本任务相关代码、配置和测试。
2. 说明当前调用链。
3. 明确本轮唯一目标。
4. 列出允许修改的文件。
5. 列出禁止修改的文件。
6. 说明输入、输出和数据结构。
7. 说明错误处理和回滚方式。
8. 列出测试用例。
9. 给出可执行的验收命令。
10. 识别是否涉及 Git 子模块及其影响。
11. 识别是否涉及真实 API 调用。
12. 列出该里程碑的禁止扰动项。

输出：

- 当前实现；
- 实施方案；
- 修改文件；
- 风险；
- 测试；
- 验收标准；
- 回滚方式；
- 禁止扰动项；
- 子模块影响。

完成后等待人工批准，不得自动切换 Act，不自动实施。

## 规划前置检查

- 必须先检查 `git status`、当前分支和子模块状态。
- 若工作区存在非当前里程碑修改、子模块 dirty 或分支不符，必须停止并报告，不得覆盖现有修改。
- 一次只规划一个里程碑。
