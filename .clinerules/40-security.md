# 安全规则

## 密钥与敏感信息

- 密钥（API Key、Token、数据库密码、SMTP密码等）禁止进入源码。
- 密钥禁止输出到日志、错误消息和调试信息。
- `.env` 必须被 Git 忽略，不得提交。
- 真实密钥通过环境变量或本地配置文件注入，不在代码中保存。

## 网络请求

- 只允许 `http` 和 `https` 协议，禁止允许其他协议（如 `file`、`ftp`、`gopher` 等）。
- 所有外发请求必须有超时设置和有限重试。

## SSRF 防护

- 所有由用户输入或来源配置驱动的 URL 请求必须执行 SSRF 防护。
- 禁止访问 `localhost`、`127.0.0.1`、`::1`、`0.0.0.0` 及私有 IP 段（如 `10.x`、`172.16-31.x`、`192.168.x`、`169.254.x` 等）。
- 解析重定向时必须重新校验目标地址，防止通过重定向绕过防护。
- 目标地址校验应在 DNS 解析后再次执行，防止 DNS 重绑定绕过。

## PDF 文件安全

- PDF 文件必须校验文件头和大小。
- 必须限制 PDF 文件大小上限（上限值在 M5 实施时配置化）。
- 文件头校验用于确认文件确实是 PDF（以 `%PDF` 开头），防止伪装文件。

## 路径安全

- 所有涉及文件路径的操作必须防护路径穿越（Path Traversal）。
- 用户输入的文件名/相对路径必须规范化并校验，禁止包含 `..` 或绝对路径逃逸到允许目录之外。

## 部署安全

- MongoDB 容器不得公开映射端口到公网。
- 管理界面不得直接公开到公网，必须通过内网访问或反代保护。
- Docker 容器必须使用非 root 用户运行。
- 容器间通信使用内部网络，不对外暴露不必要的端口。

## 日志安全

- 日志必须脱敏：不得记录密钥、Token、密码、Cookie 等敏感字段。
- 日志必须轮转，避免无限增长耗尽磁盘。
- 轮转策略需在部署中配置（如按大小或按天轮转）。
